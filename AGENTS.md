# Правила разработки

## Архитектура

- Слои: `app → pages → widgets → features → entities → shared`.
- Нижний слой не импортирует верхний.
- Контакт и заявка — разные сущности. Не объединять их.
- Реактивные чтения в страницах могут использовать типизированную Dexie-БД; бизнес-операции и массовые записи идут через сервисы.
- Любая массовая запись выполняется транзакцией.

## UI / Design System

Дизайн-система проекта — Material UI поверх темы и токенов из `src/shared/design-system`.
Использовать её обязательно, обходные пути не допускаются.

- Сначала готовый компонент Material UI, и только потом свой. Перед тем как собирать
  интерфейс из `Box`, `ButtonBase` и `sx`, проверьте, есть ли штатный компонент:
  `Stepper`, `Autocomplete`, `Accordion`, `Tabs`, `Badge`, `List`, `Skeleton` и другие.
  Свой компонент допустим, только если аналога в MUI нет; в файле пишется комментарий,
  почему готовый не подошёл.
- Готовый компонент настраивается его собственными пропами и слотами (`icon`, `slots`,
  `slotProps`, `variant`, `size`), а не переписыванием разметки.
- Сырые HTML-теги в компонентах запрещены. Единственное исключение — обёртки, которых
  требует сама MUI: `<span>` вокруг заблокированной кнопки внутри `Tooltip`.
- Точка-разделитель («·», «•») в текстах интерфейса запрещена. Части строки
  разделяются запятой. Проверяется скриптом `check:tokens`.
- Цвета только из палитры темы (`error.main`, `text.secondary`, `action.disabled`,
  `divider`) или из данных. Случайные HEX/RGB в компонентах запрещены.
- Отступы, радиусы, тени и типографика берутся из темы или токенов.
- Размеры (`width`, `height`, `borderRadius`, `fontWeight`, `fontSize`) — из `tokens`.
  Радиус в `sx` берётся только из `tokens.radiusCss`: числовой `borderRadius` MUI
  умножает на `shape.borderRadius` темы, и `tokens.radius.md` превращается в 144px.
  Нужного значения нет — добавьте ключ в `tokens`, а не пишите число в `sx`.
- Правки темы и общих стилей идут в `src/shared/design-system`, а не в отдельные компоненты.
  Описание системы продублировано в `.layout/` (`layout.md`, `tokens.css`) и проверяется
  скриптом `check:design` (`@layoutdesign/context`); при изменении токенов обновите оба места.
- У каждого действия есть loading, empty, error и success-состояние.
- Смысл нельзя передавать только цветом. Клавиатура и видимый focus обязательны.

## Качество

- Production-файл: до 350 строк. Тест: до 500 строк.
- TypeScript strict; `any`, пустые `catch`, необработанные Promise запрещены.
- Новая бизнес-логика получает unit/integration-тест.
- Импорт, дедупликация, напоминания и backup считаются критическими зонами.
- Перед сдачей: `npm run quality` и `npm run check:aislop`.
- Aislop не заменяет линтер, типы и тесты.
