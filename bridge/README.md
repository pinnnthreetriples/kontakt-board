# Мост к MAX

Локальный HTTP-сервер, через который приложение отправляет КП в мессенджер MAX.
Отдельная программа для этого больше не нужна: мост живёт здесь, поднимается
вместе с приложением и хранит свою сессию сам.

## Зачем он вообще нужен

Браузер не может подключиться к MAX напрямую:

- протокол двоичный (msgpack со сжатием LZ4/zstd поверх WebSocket);
- сервер MAX ждёт заголовок `Origin: https://web.max.ru`, а браузер подставляет
  туда собственный адрес страницы и подменить его не даёт.

Поэтому рядом с приложением работает небольшой процесс на Python, а страница
общается с ним обычным JSON на `http://127.0.0.1:8765`.

## Как запускается

`START_WINDOWS.cmd` открывает приложение и в отдельном окне запускает
`scripts/start-bridge.ps1`. Скрипт при первом запуске создаёт
`%LOCALAPPDATA%\KontaktBoard\bridge-venv` и ставит туда закреплённые версии из
`requirements.txt`, дальше просто запускает мост. Интернет нужен только при
первой установке и после смены зависимостей.

Окружение лежит на локальном диске, а не рядом с программой: тогда саму
программу можно держать на флешке и носить между компьютерами. Каждый компьютер
ставит своё окружение под свой Python, а смена буквы диска ничего не ломает.

Требуется Python 3.10 или новее. Если его нет, окно моста скажет об этом и
подскажет, что установить.

Запустить мост отдельно (например, вместе с `npm run dev`):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-bridge.ps1
```

## Что где лежит

| Файл | Ответственность |
| --- | --- |
| `bridge.py` | точка входа: аргументы, логи, запуск сервера |
| `http_api.py` | маршруты, CORS и перевод результатов в JSON |
| `service.py` | связка рантайма, состояния авторизации и журнала |
| `runtime.py` | поток с PyMax: подключение, сессия, отключение |
| `auth_flow.py` | вход по QR-коду и по SMS, с мгновенной отменой |
| `session_store.py` | файлы сессии и способ, которым её открыли |
| `sending.py` | поиск получателя и отправка одного КП |
| `history.py` | журнал отправок, защита от повторов |
| `state.py` | конечный автомат авторизации |
| `phones.py` | нормализация номеров |
| `qr.py` | отрисовка QR-кода входа |
| `transport.py` | строгий TLS и отправка текста без Markdown |

Сессия MAX (`session\session.db`) и журнал отправок (`send_ledger.sqlite3`)
хранятся в `%LOCALAPPDATA%\KontaktBoard`, а не в папке программы: обновление
приложения не должно разлогинивать оператора.

Ключ журнала — номер плюс точный текст сообщения. Поэтому одно и то же КП второй
раз не уйдёт, а другой текст тому же человеку уйдёт свободно. Если отправка
оборвалась и её исход неизвестен, запись остаётся незакрытой и блокирует повтор
этой пары навсегда: это осознанный выбор в пользу «лучше не отправить, чем
отправить дважды». Разблокировать можно только удалив `send_ledger.sqlite3`
целиком, поэтому делайте это, только убедившись в переписке MAX, что КП не
дошло.

## Два способа входа

- **QR-код.** Web-клиент PyMax поверх WebSocket. MAX даёт на код ровно 120 секунд,
  поэтому мост сам заменяет истёкший код новым, пять раз подряд. Ссылка под кодом
  показывается всегда: её можно открыть прямо на телефоне, если сканировать нечем.
- **Номер телефона и код из SMS.** Мобильный клиент PyMax поверх TCP: коды в SMS
  MAX присылает только приложению, web-режим их не запрашивает.

Сессии этих режимов не взаимозаменяемы, поэтому рядом с `session.db` лежит
`session_mode.json` с выбранным способом и номером. После перезапуска мост
подключается тем же клиентом, каким сессия была открыта.

## Важные решения

- **Никакого автоматического повтора отправки.** Обрыв связи неотличим от
  отказа, поэтому статус честно возвращается как `UNKNOWN`, а журнал блокирует
  повтор с тем же текстом. Дубль КП клиенту дороже, чем ручная проверка.
- **Повторный вход не начинается сам.** Если MAX отозвал сохранённый токен, мост
  сообщает об этом и ждёт действия оператора, а не показывает новый QR в фоне.
- **CORS без звёздочки.** Разрешены только адреса приложения, рабочий порт
  передаёт лаунчер ключом `--origin`. Иначе любой открытый сайт смог бы читать
  состояние авторизации и слать сообщения от имени оператора.
- **Корень ISRG Root X2 лежит рядом.** Windows не кэширует его, и OpenSSL внутри
  Python падает на `api.oneme.ru` там, где браузер работает. Отпечаток файла
  закреплён в `transport.py`: подменённый якорь доверия останавливает соединение.
