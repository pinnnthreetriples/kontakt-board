# Архитектура

## Почему это офлайн PWA

Для первого пользователя отдельный сервер и авторизация не нужны. Готовая Windows-сборка запускает статические файлы на loopback-интерфейсе, приложение устанавливается через Chrome/Edge, работает без интернета и хранит данные в IndexedDB через Dexie. Это быстрее и проще для MVP, чем поддержка нативной оболочки.

## Слои

- `app` — запуск, маршруты, тема;
- `pages` — экраны;
- `widgets` — крупные блоки страниц;
- `features` — импорт, backup, карточка контакта;
- `entities` — бизнес-операции заявок;
- `infrastructure` — локальная БД и миграции;
- `shared` — типы, токены, общие функции.

## Данные

`Contact` хранит человека/организацию. `Lead` хранит конкретную заявку и её этап. Поэтому новый запрос того же человека не уничтожает старую заявку.

Комментарии, звонки и история хранятся отдельно и не перезаписываются Excel-импортом.

У этапов есть отдельное назначение (`normal`, `no_answer`, `won`, `lost`), поэтому переименование колонки не ломает отчёты и сценарий «не дозвонились». Порядок активных этапов всегда нормализуется внутри транзакции.

## Масштабирование

При переходе к команде:

1. PostgreSQL становится источником данных.
2. Добавляются backend API, авторизация и роли.
3. Локальные сервисы заменяются API-клиентом.
4. UI и доменные сущности сохраняются.

Не нужно синхронизировать несколько локальных баз между компьютерами.
